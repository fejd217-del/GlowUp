# GlowUp Club — платёжный бот

Для Railway смотри RAILWAY_RU.md: запуск через Variables, без локального config.json, один сервис для бота и сайта.

Это отдельный бот. Он не запускает загрузчик и не редактирует материалы форума. База — Supabase. Для криптооплаты установи зависимости из requirements.txt. Python 3.10 или новее.

## Что готово

Главное меню по примеру видео: оформление доступа, пробный вход на пять минут, состав материалов, мой доступ, поддержка. Кнопки используют штатные цвета Telegram. Для главного меню можно загрузить свою обложку через админку. Premium-эмодзи подключаются по ID в `custom_emoji_ids`; доступность зависит от условий Telegram. Без них остаются обычные эмодзи.

Оплата — Telegram Stars. Тарифы: 30 дней, 90 дней, без срока. Цена каждого настраивается; изначально продажи закрыты. Оплата разовая, без автоматического списания. Продление добавляет дни к оставшемуся сроку. Отдельный заказ содержит свою сумму и срок: изменение цены в админке не меняет уже выписанный счёт.

Пробный период доступен один раз и начинается после вступления. Ссылка работает десять минут, а заявку бот принимает только от нужного аккаунта. Пересылка ссылки другому человеку доступа ему не даёт. После окончания оплаченного или пробного срока бот удаляет только участников, которых сам принял; владельца и администраторов не удаляет. Старые участники форума автоматически не переводятся в пробный период.

## Админ-панель

Открывается кнопкой в меню или `/admin`, только для `admin_ids`.

- Число пользователей, активных доступов, оплат, полученных Stars и открытых обращений.
- Пользователи с пагинацией и поиск по Telegram ID.
- Карточка участника: срок, пробный период, блокировка; выдача, продление, отзыв и блокировка доступа.
- Оплаты с пагинацией, деталями и полным возвратом Stars с подтверждением. При возврате срок пересчитывается из оставшихся выдач.
- Обращения, последние ответы, ответ пользователю и закрытие обращения.
- Промокоды с процентом скидки и лимитом. Один аккаунт — одно использование. Место по коду резервируется при создании счёта, даже если он не был оплачен; это видно в счётчике.
- Текстовые рассылки: предпросмотр, подтверждение, прогресс, остановка. При сбое доставки запись считается ошибкой; повторная отправка тому же получателю автоматически не делается.
- Цены, включение/остановка продаж, загрузка обложки.
- Журнал административных и платёжных действий. Администраторы добавляются в `admin_ids` файла `config.json`.

## Запуск на Windows

1. Создай нового бота в `@BotFather`. Старого загрузчика используй отдельно. Не запускай два процесса с одним токеном.
2. Добавь нового бота администратором GlowUp Club. Дай права **приглашать пользователей** и **блокировать участников**. Форум должен быть приватным. Проверь старые приглашения: ссылки, созданные тобой, этот бот сам не отключает и вход по ним не контролирует.
3. Создай проект Supabase. В SQL Editor вставь весь `schema.sql` и выполни. Миграция создаёт только таблицы и функции с префиксом `glow_`. Не используй для этого чужую базу без понимания её структуры.
4. Для проверки базы можно отдельно выполнить `test_database.sql`. Это интеграционный тест с откатом, он не делает Telegram-платежей. В этой среде его не запускали: подключение к твоему Supabase ещё не выполнено.
5. В PowerShell из папки бота:

```powershell
py bot.py setup
```

Введи свой Telegram ID (можно оставить пустым), цены в Stars (можно оставить пустыми), **Project URL**, **legacy service_role key** Supabase и токен нового бота. Ключ `anon` не подходит. Токен и ключ вводятся скрыто и сохраняются в локальном `.env`. Этот файл не отправляй другим и не добавляй в публичный репозиторий.

6. Проверь подключение:

```powershell
py bot.py check
```

7. Запусти:

```powershell
py bot.py run
```

Если ID не был задан, консоль покажет команду `/claim КОД`. Отправь её новому боту в личку в течение десяти минут. Привязка разрешена только администратору форума. Затем открой `/admin`.

8. Проверь меню, пробный доступ **с другого аккаунта, который ещё не состоит в форуме**, обращения и ручную выдачу. Через админку задай цены и открой продажи. Настоящая проверка оплаты требует реального платежа Stars; возврат можно проверить в той же админке. Не считай локальные тесты подтверждением работы платёжного API.

## Supabase и секреты

Данные пользователей, заказы, платежи, доступы, приглашения, обращения, промокоды, рассылки и журнал хранятся в Supabase. Таблицы защищены RLS и недоступны ролям `anon` и `authenticated`. Серверный `service_role` может обращаться к ним; ключ хранится только у процесса бота. `config.json` — несекретные тексты и настройки. Цены, статус продаж и обложка также сохраняются в Supabase. В новой локальной копии нужно вручную перенести `admin_ids` и настройки чата.

## Работа после остановки

Данные сохраняются, но сам Supabase не запускает код бота. Если закрыть PowerShell, новые платежи, заявки и проверка окончания сроков будут ждать следующего запуска. Для круглосуточной работы нужен постоянно работающий компьютер или сервер. Telegram хранит входящие обновления ограниченное время; не оставляй платёжного бота выключенным надолго. Без подключения реального проекта не обещается работа 24/7.

После запуска бот дочитает сохранённые обновления и проверит закончившиеся сроки. Аренда процесса в Supabase предотвращает обычный запуск двух копий одновременно. После аварийной остановки может понадобиться подождать до 90 секунд перед перезапуском.

При неопределённом результате возврата в карточке оплаты будет «ожидает сверки». Проверь историю Stars; уведомление Telegram о возврате пересчитает доступ. Двойное уведомление о той же оплате не продлевает срок второй раз.

## Что ещё не подключено

Живые Supabase и Telegram, фактические цены и ID Premium-эмодзи. Две готовые обложки включены в assets; при первом открытии меню бот загрузит их и сохранит Telegram file_id. Криптоплатежей и автоматического списания нет. Каталог пока содержит честное описание опубликованных текстов; названия отсутствующих видео и курсов не выдаются за загруженные материалы.

Локально выполнено 19 тестов: суммы и владелец счёта, закрытые продажи, повторы, личные ссылки, пробный доступ, ограничения админки, подтверждение действий и предпросмотр рассылок. API Telegram и PostgreSQL в этих тестах заменены тестовыми объектами.

## Обложки

В комплекте две готовые картинки GlowUp: главное меню и доступ. Первый показ автоматически загружает нужную картинку в Telegram. Кеш file_id хранится в Supabase. Своя картинка из админки заменяет главную обложку. После изменения картинок вручную убери соответствующий кеш screen_photo_file_ids. Криптоплатежи ещё не подключены: для отдельной страницы оплаты нужны публичный адрес, монета и сеть.

## USDT в сети TON — отдельный сайт

Добавлены `checkout.py`, папка `checkout`, `crypto.py` и `crypto_schema.sql`. Внутри Telegram покупка цифрового доступа остаётся через Stars. Криптосчета создаются на самостоятельном сайте. Ссылка на криптопокупку в меню бота не добавляется. Сам факт наличия отдельного сайта не гарантирует соответствие правилам Telegram: перед публикацией проверь свой способ продажи по https://core.telegram.org/bots/payments-stars.

Что работает в коде:

- Подключение покупателя через настоящий Telegram-аккаунт: сайт открывает бота, бот привязывает сессию. Telegram ID вводить вручную не надо.
- Счёт с фиксированными ценой, сроком и получателем. Комментарий `GLOW...` определяет конкретный счёт. Срок оплаты — 30 минут.
- QR, ссылка Tonkeeper, копирование адреса и комментария, статус оплаты.
- Проверка сырых транзакций TonAPI: только уведомления от USDT-кошелька, полученного через официальный USDT master. TON, сторонние токены, неуспешные и повторные транзакции не дают доступ.
- Недоплаты суммируются. Если точная сумма поступила вовремя, доступ добавляется один раз. Переплата видна в истории, но не добавляет ещё один тариф.
- Поздние переводы и переводы без комментария проверяет админ. Подтвердить счёт без фактически найденной полной суммы нельзя.
- Остановка новых продаж USDT не прекращает проверку ранее созданных счетов.
- Возврат админ сначала отправляет самостоятельно из своего кошелька. Бот только записывает выполненный возврат и отзывает соответствующий доступ. Ключей кошелька в проекте нет.

Подключение:

1. Для нового проекта сначала выполни `schema.sql`, затем `crypto_schema.sql` в SQL Editor Supabase. Для уже настроенной базы достаточно второго файла.
2. В папке проекта выполни `py -m pip install -r requirements.txt`.
3. В `.env` укажи `CRYPTO_WALLET_ADDRESS` — публичный адрес обычного TON mainnet кошелька, `CHECKOUT_BASE_URL=https://твой-домен`, `TONAPI_KEY` — ключ TonAPI. Seed-фразу и приватный ключ нигде не вводи.
4. Для первого запуска бота: `py bot.py setup`, затем `py bot.py check` и `py bot.py run`. Для уже настроенного бота достаточно перезапуска.
5. Во втором окне запусти `py checkout.py`. По умолчанию он слушает только `127.0.0.1:8080`. Нужен HTTPS reverse proxy с доменом, например Caddy. Отдельный файл `Caddyfile.example` показывает настройку. Без HTTPS cookie подключения не работает. Это не сайт, уже размещённый в интернете.
6. В админке: «USDT · оплаты» → задай цены тарифов → «Включить / выключить» → подтверди. Без цен и адреса продажи закрыты.
7. До публичного запуска сделай тестовую покупку небольшой суммы: проверь привязку аккаунта, реальный перевод USDT с комментарием, выдачу доступа и отображение в админке. Здесь реальные переводы и твоя Supabase не проверялись.

Разбор платежей в админке:

- Открой счёт: полученная сумма, состояние, пользователь и ссылки на найденные транзакции.
- Для поздней полной оплаты нажми «Подтвердить доступ» и подтверди действие.
- Для перевода без комментария: `/crypto_assign ХЕШ_НАЙДЕННОГО_ПЕРЕВОДА GLOWномер`. Хеш берётся из списка переводов без счёта. Проверь, кому принадлежит перевод, до подтверждения.
- После самостоятельно выполненного возврата: `/crypto_refund GLOWномер ХЕШ_ВОЗВРАТА`. Это запись админа о возврате, а не автоматическая проверка исходящей транзакции или перевод денег.

Сайт и бот должны работать постоянно. Проверка цепочки примерно раз в 30 секунд, при очереди транзакций может занять дольше. Используется доверенный индексатор TonAPI, собственный TON-узел не запускается. Первичная проверка охватывает последние 7 дней и более раннюю дату неоплаченных счетов; при долгом отключении счёт не исчезает из базы. Переводы, для которых нет счёта и которые старше окна проверки, разбираются отдельно. Перед запуском укажи свои условия доступа, возвратов и обработки данных в конфиге и на сайте.

Проверки: `py -m unittest discover -s . -p "test_*.py"`. SQL-сценарии в `test_database.sql` и `test_crypto_database.sql` запускаются отдельно после схем в тестовой Supabase, затем откатываются. В текущей среде SQL не выполнялся.
