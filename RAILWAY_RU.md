# Railway: один сервис для бота и сайта

Хранилище остаётся Supabase. Railway запускает приложение; Neon и DATABASE_URL этому проекту не нужны.

1. В Supabase SQL Editor выполни `schema.sql`, затем `crypto_schema.sql`. Если первая схема уже выполнена, повторять её не обязательно. Не включай продажи до проверки своей базы.
2. Загрузи содержимое папки GlowUp_paybot в корень GitHub-репозитория. Если папка лежит внутри репозитория, выставь Railway Root Directory `/GlowUp_paybot`.
3. Подключи репозиторий к Railway. Dockerfile и railway.json уже готовы. Start Command — `python -u railway.py`. Оставь **одну реплику**, выключи Serverless/App Sleeping. Локально этот же токен одновременно не запускай.
4. Variables → Raw Editor: вставь значения из блока ниже. Значения-заглушки замени своими; токены не выкладывай в GitHub.
5. Выполни Deploy. Бот должен быть админом приватного форума с правами приглашения и блокировки участников. В логах будет «Проверено» и «Бот работает».
6. Networking → Generate Domain. Скопируй HTTPS адрес Railway в CHECKOUT_BASE_URL, добавь CRYPTO_WALLET_ADDRESS и TONAPI_KEY, затем примени переменные. Второй сервер и Caddy не нужны: Railway обслуживает HTTPS, сайт читает PORT автоматически.
7. В Telegram /admin → «USDT · оплаты»: задай цены, затем включи продажи. Цены Stars задаются отдельно. Сначала проверь небольшой реальный перевод и выдачу доступа.

Обязательные переменные для первого запуска:

```env
BOT_TOKEN=токен_нового_платежного_бота
SUPABASE_URL=https://твой-проект.supabase.co
SUPABASE_SERVICE_ROLE_KEY=твой_service_role_ключ
CHAT_ID=-1004358476982
ADMIN_IDS=твой_числовой_Telegram_ID
TRIAL_MINUTES=5
PYTHONUNBUFFERED=1
```

Для сайта USDT добавь:

```env
CHECKOUT_BASE_URL=https://твой-домен.up.railway.app
CRYPTO_WALLET_ADDRESS=публичный_TON_mainnet_адрес
TONAPI_KEY=твой_ключ_TonAPI
```

ADMIN_IDS можно задать через запятую для нескольких админов. Числовой Telegram ID можно получить командой /id в боте. Если ADMIN_IDS ещё неизвестен, не задавай его: после запуска получишь временный код /claim в логах, который работает только для администратора форума. Не используй ID загрузчика или ID группы вместо своего ID.

CHECKOUT_BASE_URL — точный HTTPS адрес без пути и без завершающего слэша. PORT задаёт Railway; руками его менять не надо. CHECKOUT_HOST в Railway уже выставляется автоматически. Получатель — публичный адрес кошелька; seed-фраза и приватный ключ не нужны.

Тарифы, админская привязка через /claim и оформление сохраняются в Supabase и переживают перезапуск контейнера. ADMIN_IDS, CHAT_ID и TRIAL_MINUTES из Variables имеют приоритет. Локальные файлы Railway временные, поэтому единственное хранилище данных проекта — Supabase. При смене админов меняй ADMIN_IDS в Variables.

После перевыкладки бот может до 90 секунд ждать освобождения аренды предыдущего процесса. Это не повторная загрузка материалов. Если ожидание не заканчивается — проверь, что осталась одна реплика и нет другого процесса с тем же токеном.

Локальные Python-проверки прошли. Реальное подключение к твоей Supabase, деплой Railway и настоящая оплата здесь не выполнялись. SQL-тесты входят в архив, но в этой среде не запускались: локальный PostgreSQL не удалось запустить. Запусти их в тестовой Supabase, они откатывают свои изменения.
